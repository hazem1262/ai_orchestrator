# S9 — Remote access (Tailscale serve, PWA push, passkeys, Slack DM)

Date: 2026-09-27 · tailscale 1.102.3 · macOS 26.7 (25G229) · iOS — · Android —

**Status: read-only checks done; every live check (a–h) is pending the manual steps below.**

## Question

Can a phone reach the local daemon only through `tailscale serve`, install the app as a PWA, get a Web Push, pass a passkey step-up, and answer a session through a Slack self-DM? The answer sets the go/no-go for Phase 6 Tasks 12–19 and the facts (b), (c), (d), (e), (g), (h) that Tasks 2, 12, 15 and 16 read (see Task 1 in [`../phase-6-linear-slack-remote.md`](../phase-6-linear-slack-remote.md)).

## Method

This run was unattended, so it ran only read-only commands, each under `timeout`:

- `tailscale version`, `tailscale status --json` (summarised with `node`, nothing written).
- `sw_vers`, `which security` (no Keychain item was read or written).
- `node -v`, `pnpm -v`, `npm view <pkg> version` for each Phase 6 dependency.

It did not run `tailscale serve`, `tailscale serve status`, `tailscale funnel`, `up` or `set`. It sent no Slack message, called no Linear or Slack API, registered no passkey and installed nothing. The spike package in `spikes/s9-remote/` (Task 1, Steps 1–3) was not created in this run; the manual steps below create it.

## Manual steps (for the user)

Do these in order and paste each result into the table under "Results".

1. Install Tailscale on the phone(s), log in as `hazem@wakecap.com`, and confirm the phone shows in `tailscale status`.
2. Create the spike package from Task 1, Steps 1–3, then:
   ```bash
   cd /Users/hazem/orchestrator/spikes/s9-remote && pnpm install --ignore-workspace
   tailscale serve --bg http://127.0.0.1:4399
   tailscale serve status --json > /tmp/s9-serve-status.json; cat /tmp/s9-serve-status.json
   S9_ORIGIN="https://hazems-macbook-pro.tailc6e70.ts.net" S9_LOGIN="hazem@wakecap.com" pnpm serve
   ```
   The spike uses port 4399. The real daemon later uses `tailscale serve --bg http://127.0.0.1:4317`; the headers seen should be the same.
3. **(a)** Open the origin on the phone with Tailscale on (page loads) and off, on cellular (page does not load).
4. **(b)** Tap **Headers**. Record `socket`, `host`, `x-forwarded-for`, `x-forwarded-host`, `x-forwarded-proto`, `tailscale-user-login`.
5. **(c)** From another tailnet device: `curl -s -H 'Tailscale-User-Login: evil@example.com' https://hazems-macbook-pro.tailc6e70.ts.net/headers`. The response must show the real login (or none for a tagged device), not `evil@example.com`.
6. **(d1)** Android Chrome: **Enable push** → **Send test push** → the notification arrives; tapping it opens `/?from=push`.
7. **(d2)** iOS Safari: Share → **Add to Home Screen** → open the installed app → **Enable push** → lock the phone → **Send test push** from the Mac (`curl -X POST http://127.0.0.1:4399/push`) → the notification arrives; tapping it opens the app.
8. **(e1)** On the phone: **Register passkey** → Face ID → `verified: true`; then **Step-up** → `verified: true`.
9. **(e2)** Same flow in desktop Safari or Chrome at the ts.net origin. Note whether the iCloud Keychain passkey also shows on the phone.
10. **(f)** **Send reply** → the server logs `REPLY RECEIVED: yes, continue`.
11. **(g1)** In the Slack app's **OAuth & Permissions**, add `http://127.0.0.1:4317/api/connectors/slack/callback`. Record whether Slack accepts it.
12. **(g2, g3)** `SLACK_USER_TOKEN=xoxp-… pnpm slack`. Record whether the phone notifies for the self-DM. Reply "hello" from the phone, press Enter, and record `app_id` / `bot_id` on the posted root and on the typed reply.
13. **(g4)** `S9_TRY_REMINDER=1 SLACK_USER_TOKEN=xoxp-… pnpm slack`. Record whether the Slackbot reminder notifies the phone about 60 s later.
14. **(h)** `tailscale funnel --bg 4399` for 30 seconds only, then `tailscale serve status --json` and record the `AllowFunnel` key. Then `tailscale funnel --https=443 off` and confirm `AllowFunnel` is gone. If the tailnet policy refuses Funnel, record the error text instead.
15. Clean up: `tailscale serve --https=443 off`, then confirm `tailscale serve status` is empty.

## Decision
