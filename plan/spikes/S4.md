# S4 — AGNC over MCP from a local app

Date: 2026-09-27 · SDK: @modelcontextprotocol/sdk 1.30.1 (plan `^1.30.0`) · endpoint: https://agnc.wakecap.ai/mcp

**Status: read-only checks done. Every live check (a–f) is pending the manual steps below.**

## Question

Can the local daemon connect to AGNC over MCP (Streamable HTTP) with OAuth, list only my sessions, read their detail, and keep the token across restarts? The answer picks the GO or NO-GO branch of Tasks 20–21 in [`../phase-7-automations-compare-supervisor.md`](../phase-7-automations-compare-supervisor.md).

## Method

This run was unattended, so it ran only read-only commands, each under `timeout 20` (the install under `timeout 300`):

- `npm view` for the SDK and `tsx`.
- Unauthenticated `GET` of the OAuth discovery documents.
- One unauthenticated `POST /mcp` with a JSON-RPC `initialize` body.
- `npm install --no-save` in `spikes/s4-agnc` and a `tsc --noEmit` typecheck of `probe.ts`.

It did not run `probe.ts`. It did not open a browser, register a client (no request to `/mcp/oauth/register`), request a token, send `tools/list` or `tools/call`, create an AGNC session or send a prompt. No token was written anywhere.

### Authorization-server metadata (RFC 8414)

```
$ curl https://agnc.wakecap.ai/.well-known/oauth-authorization-server           → 200 application/json
$ curl https://agnc.wakecap.ai/.well-known/oauth-authorization-server/mcp/oauth → 200 application/json (same body)
$ curl https://agnc.wakecap.ai/.well-known/openid-configuration                 → 404 text/html (the web app's "Not found." page)
$ curl https://agnc.wakecap.ai/mcp/oauth/.well-known/oauth-authorization-server → 404
```

| Key | Value |
|---|---|
| `issuer` | `https://agnc.wakecap.ai/mcp/oauth` |
| `authorization_endpoint` | `https://agnc.wakecap.ai/mcp/oauth/authorize` |
| `token_endpoint` | `https://agnc.wakecap.ai/mcp/oauth/token` |
| `registration_endpoint` | `https://agnc.wakecap.ai/mcp/oauth/register` (dynamic client registration, RFC 7591) |
| `response_types_supported` | `["code"]` |
| `grant_types_supported` | `["authorization_code", "refresh_token"]` |

| `token_endpoint_auth_methods_supported` | `["none"]` (public clients only) |
| `scopes_supported` | same six scopes as above |

The SDK's discovery order tries the path-aware URL `/.well-known/oauth-authorization-server/mcp/oauth` first, and that URL answers. There is no OpenID Connect discovery, which the SDK does not need.

### Unauthenticated `initialize`

```
$ curl -X POST https://agnc.wakecap.ai/mcp \
    -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
    -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"orc-spike-s4-check","version":"0.0.0"}}}'
200 application/json
{"jsonrpc":"2.0","id":1,"result":{"protocolVersion":"2025-03-26","serverInfo":{"name":"agnc","version":"0.1.0"},"capabilities":{"tools":{}},"instructions":"Use AGNC tools to inspect and operate user-scoped AGNC coding sessions."}}
```

Findings:

1. `initialize` needs no credentials. There is no `WWW-Authenticate` header and no `Mcp-Session-Id` header, so the server looks stateless.
2. The server negotiates protocol version `2025-03-26`, not the `2025-06-18` the client offered. SDK 1.30.1 accepts `2025-03-26`.
3. The 401 that starts OAuth can only come on a later request (`tools/list` or `tools/call`). I think it comes on `tools/list`, but that is not checked; it could also be an in-band `isError` tool result. Per the spike rules, no further request was sent after this response.

Because of finding 1, `client.connect()` succeeds without a token and never throws `UnauthorizedError`. `probe.ts` therefore calls `listTools()` inside the same `try` as `connect()`, so the first 401 still starts the OAuth flow.

### `probe.ts` typecheck

```
$ cd spikes/s4-agnc && tsc --noEmit --module nodenext --moduleResolution nodenext --target es2022 --strict --skipLibCheck --types node probe.ts
(no output, exit 0)
```

`probe.ts` differs from the plan's Task 19 Step 2 in two places:

- `textOf` takes `Record<string, unknown>`. In SDK 1.30.1, `callTool` returns a union that includes the legacy `{ toolResult }` shape, and the plan's parameter type does not accept it (`TS2345`).
- `connect()` calls `listTools()` inside the `try`, for the reason above.

### Other evidence

The AGNC connector in claude.ai (`claude.ai AGNC` MCP server) uses the same server with OAuth and exposes `agnc_auth_status`, `agnc_list_sessions`, `agnc_get_session`, `agnc_list_messages`, `agnc_list_events`, `agnc_send_prompt`, `agnc_create_session`, `agnc_create_pr`, `agnc_health`, `agnc_get_model_default` and `agnc_set_model_default`. This shows a third-party client can register and get tokens. It does not show that a loopback redirect URI is accepted. None of these tools were called.

## Decision

**GO (unconfirmed).** The metadata shows OAuth 2.1 as the MCP authorization spec expects it: protected-resource metadata, an authorization server with PKCE `S256`, `authorization_code` + `refresh_token`, dynamic client registration, and public clients (`token_endpoint_auth_method: none`). A local app can do all of that. Nothing observed requires a client secret, a pre-registered client id or a non-loopback redirect.

The decision turns to **NO-GO** if (a), (c) or (e) fails in the manual steps, as Task 19 Step 5 says. Then Phase 7 ships only the link-out card (Task 20 Step 1), `agnc.enabled` stays `false`, and this file records the blocker.

**Required adjustment to Task 20 Step 5 (observed, not a manual-step result):** the plan's `getClient()` treats a successful `client.connect()` as authorised. AGNC answers `initialize` without a token, so `beginAuth()` would return `{ authorizationUrl: null }` ("already authorised") and `pendingAuth` would never be set, making `finishAuth` fail with `no OAuth flow in progress`. `getClient()` must send one authenticated request (`client.listTools()`) after `connect()` inside the same `try`, and only then set `live`. If the manual steps show the 401 comes on `tools/call` instead, `call()` must also set `pendingAuth` when `callTool` throws `UnauthorizedError`. The fake server in `apps/daemon/test/fakes/agnc-server.ts` should allow `initialize` without a token so the tests cover this.
